## Proposed responsibility boundaries

The creative agent interprets the brief, proposes concepts, builds a storyboard, assigns references, writes prompts, and recommends revisions. The production system owns authoritative scene versions, budget reservations, provider request IDs, asset storage, retry limits, cancellation, and export. An agent conversation should not be the only record of paid work.

Candidate pipeline, subject to interview:

Song and brief -> audio/lyric timing -> concept -> character/location references -> timed storyboard -> provider-specific prompts -> generation jobs -> technical and visual review -> timeline assembly with original audio -> export.

Keep a shared scene representation with provider adapters. The existing VRGDG export can be an adapter if compatibility matters; do not silently make its MiniMax-specific fields the universal data model.

fal provides an example of asynchronous generation with persistent request IDs, polling, webhooks, and cancellation. This demonstrates a usable provider integration pattern, not a decision to select fal. Store provider job identifiers before subsequent work and reconcile uncertain submissions before retrying. [Official queue API](https://fal.ai/docs/documentation/model-apis/inference/queue)
