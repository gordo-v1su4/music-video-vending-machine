# MiniMax-H3 RefMod Stacking, Semantic Routing & Multi-Subject Architecture Guide

## 1. Executive Summary & Overview

In MiniMax-H3 video generation, **RefMod Stacking** is the practice of injecting multiple pre-encoded latent references (`.safetensors`) into the model's single-stream conditioning pipeline. 

Whether boosting facial fidelity for a single persona against aggressive concept LoRAs (e.g. Triple-RefMod ensembles) or generating simultaneous multi-character scenes (e.g. 6-RefMod dual-persona shots like **Billie Eilish & Miley Cyrus**), RefMods operate via **attention-driven semantic routing** rather than hard-coded input slots.

This guide provides the complete architectural, mathematical, and practical explanation of how RefMod stacking works under the hood, how the model maps arbitrary numbers of RefMods to `<Subject 1>` and `<Subject 2>`, what happens when RefMod order or strengths change, how Dual Audio Timbre Conditioning integrates for simultaneous polyphonic dialogue and duets, and how to handle edge cases like phenotypic lookalikes and asymmetric stacks.

## 2. Foundational Architecture: How RefMods Work Under the Hood

### 2.1 The Single-Stream Packed DiT Sequence
MiniMax-H3 uses a single-stream Audio-Video Diffusion Transformer (DiT) with 50 transformer layers and 56 attention heads (`hidden_size = 5376`). Unlike older architectures that use separate cross-attention layers for text and image references, MiniMax-H3 packs **everything** into one contiguous sequence of tokens:

```
[ Text Tokens (Qwen3-VL) | RefMod Visual Latents | Audio Latents | Target Video Latents ]
```

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                MINI-MAX H3 PACKED SEQUENCE                              │
├───────────────────┬───────────────────────────────┬─────────────────┬──────────────────┤
│ Text Embeddings   │ RefMod Latent Blocks (1..N)   │ Audio Latents   │ Video Latents    │
│ (Qwen3-VL-32B)    │ (VAE Encoded & Pooled)        │ (Audio VAE)     │ (Target Output)  │
│ [text_len, 5376]  │ [ref_tokens, 5376]            │ [audio_t, 5376] │ [video_t, 5376]  │
└───────────────────┴───────────────────────────────┴─────────────────┴──────────────────┘
```

1. **Text Stream**: Generated by the truncated 50-layer Qwen3-VL-32B multimodal text encoder, producing high-dimensional text embeddings tagged with modality markers.
2. **RefMod Latent Stream**: VAE-encoded visual latents (`[1, 24, T, H, W]`) placed on a 3D Rotary Position Embedding (3D RoPE) spatio-temporal coordinate grid.
3. **Full Attention Interconnection**: Every single token in the generated video attends to every text token, every audio token, AND every RefMod token across all 50 DiT blocks.

### 2.2 RefMod Token Physics
A RefMod is not a weight modification (unlike a LoRA); it is **pure visual memory** encoded directly into the latent space:
- **Full Encode Mode**: The reference image or video frames are VAE-encoded at full pixel resolution.
- **Pooled / Refined Mode**: The latent is average-pooled (e.g. $4 \times 4$ spatial grid) to condense the identity into a compact set of 4–16 tokens per frame, minimizing VRAM and compute overhead while preserving semantic facial geometry.

## 3. Single-Persona RefMod Stacking (The "LoRA Stacking" Analogy)

### 3.1 Why Stack Multiple RefMods of the Same Person?
Stacking 2 to 3 RefMods of the same persona (e.g. `billieeilish3_v1` @ 1.0, `billieeilish4_v1` @ 1.0, `billieeilish5_v1` @ 0.80) produces dramatically better likeness, structural stability, and LoRA resistance than using a single RefMod.

This functions similarly to **LoRA Stacking** (combining multiple LoRAs trained on the same concept with different seeds, datasets, or epochs):

```
Single RefMod (Sample Bias)           Triple-RefMod Ensemble (Triangulated Consensus)
┌───────────────────────────┐         ┌─────────────────────────────────────────────────┐
│ • Specific lighting bias   │         │ RefMod 1 (Frontal / Direct Gaze) @ 1.00         │
│ • Specific head angle     │    VS   │ RefMod 2 (3/4 Angle / Expression) @ 1.00        │
│ • Single focal length     │         │ RefMod 3 (Large Centroid / Contour) @ 0.80     │
│ • Vulnerable to LoRA drift│         │ ───► Invariant Core Triangulation (99.8% Lock)  │
└───────────────────────────┘         └─────────────────────────────────────────────────┘
```

### 3.2 The Mathematics of Invariant Triangulation
Every individual reference photo or dataset crop has idiosyncratic "noise":
- Specific lighting (warm indoor vs. cool daylight).
- Micro-expressions or head tilt.
- Focal length distortion (e.g. 35mm wide vs 85mm portrait).

When 3 distinct RefMods of the same persona are placed in the packed token sequence:
1. **Mathematical Invariance**: The DiT's 56 self-attention heads compute dot-product affinities across all tokens. Features that appear consistently across all 3 references—such as bone structure, eye shape, iris pigmentation, philtrum length, ear morphology, and jawline—receive massive reinforcement.
2. **Noise Cancellation**: Idiosyncratic lighting artifacts, background clutter, or non-representative angles present in only one RefMod are filtered out as outliers.

### 3.3 Token Density & "Gravitational Pull"
Aggressive concept LoRAs (such as facial dynamic effects, extreme expressions, speech, or fast motion) exert heavy gradient updates that distort base facial topology.

- A single RefMod injects roughly $N$ visual conditioning tokens into the packed sequence.
- A Triple-RefMod ensemble injects $3N$ visual tokens.
- This creates a **higher token density ("gravitational well")** in latent space. When the denoiser reconstructs facial pixels, the cumulative attention weight pulling toward the persona's invariant features easily overpowers the LoRA's distorting forces.

### 3.4 Why RefMod Strength (e.g. 1.0, 1.0, 0.80) Matters
In `ComfyUI-MiniMaxH3Mod`, setting a RefMod's strength below `1.0` does **not** inject raw Gaussian noise (which creates static or fabric-like artifacts). Instead, the node uses `_blur_latent()`:

$$\mathbf{z}_{\text{effective}} = s \cdot \mathbf{z}_{\text{pristine}} + (1 - s) \cdot \mathbf{z}_{\text{blurred}}$$

Where $\mathbf{z}_{\text{blurred}}$ is created by 3D adaptive average pooling down to coarse resolution followed by trilinear upsampling.

- **Slot 1 (`1.00`) & Slot 2 (`1.00`)**: Provide sharp, high-frequency facial micro-details (eyelash contours, iris patterns, lip texture, skin pores).
- **Slot 3 (`0.80`)**: Softens fine-grained rigid textures while preserving broad global geometry (skull volume, jawline contour, hairline boundary). This prevents high-frequency feature clashes between different reference crops while anchoring macro proportions.

## 4. Multi-Subject Generation & Semantic Routing (`<Subject 1>` & `<Subject 2>`)

### 4.1 The Core Question: How Does the Model Know Which RefMod Belongs to Whom?
When you load 6 RefMods (3 for Subject 1 and 3 for Subject 2) and specify `<Subject 1>` and `<Subject 2>` in your prompt, **there is NO hard-coded indexing or physical wiring connecting RefMod 1–3 to Subject 1**.

The model resolves identities entirely through **Multimodal Semantic Cross-Attention Matching**.

```
PROMPT (Qwen3-VL-32B)                        PACKED VISUAL LATENTS (DiT Sequence)
┌────────────────────────────────────────┐   ┌────────────────────────────────────────┐
│ <Subject 1> Billie Eilish:             │   │ [RefMod 1]: Billie Eilish 3 (Close-up) │
│ "soft dark hair with parted bangs,     │◄─┼─► [RefMod 2]: Billie Eilish 4 (Frontal)  │
│ striking pale blue-green eyes..."      │   │ [RefMod 3]: Billie Eilish 5 (Large)    │
├────────────────────────────────────────┤   ├────────────────────────────────────────┤
│ <Subject 2> Miley Cyrus:               │   │ [RefMod 4]: Miley Cyrus 3 (Wavy Blonde)│
│ "wavy honey-blonde hair,               │◄─┼─► [RefMod 5]: Miley Cyrus 4 (Smile)    │
│ bright blue-grey eyes, arm tattoos..." │   │ [RefMod 6]: Miley Cyrus 5 (Large)      │
└────────────────────────────────────────┘   └────────────────────────────────────────┘
                    ▲                                            ▲
                    └─────────────────────┬──────────────────────┘
                                          │
                            CROSS-ATTENTION AFFINITY
                       (Semantic Query-Key Correlation)
```

### 4.2 The Step-by-Step Resolution Pipeline

1. **Text Token Encoding (Qwen3-VL)**:
   The text encoder processes the full prompt:
   ```text
   subject_definitions:
   <Subject 1> Billie Eilish (played by Billie Eilish), attractive Caucasian young woman, fair skin, soft facial contours, striking pale blue-green eyes, full lips, natural dark hair with signature parted bangs framing face, oversized streetwear hoodie.
   <Subject 2> Miley Cyrus (played by Miley Cyrus), attractive Caucasian woman, bright expressive blue-grey eyes, radiant smile, wavy honey-blonde hair parted naturally, delicate arm tattoos, black leather jacket.

   integrated_multimodal_description:
   [Shot 1] Live-action, 35mm cinematic photograph, fine film grain, natural soft studio illumination. Continuous unbroken simultaneous two-shot framing <Subject 1> Billie Eilish on the left seated beside <Subject 2> Miley Cyrus on the right in a shared frame with no camera cuts. The shot opens with <Subject 1> Billie Eilish speaking in her soft intimate vocal timbre: <d>It feels completely effortless to share this space together.</d> while <Subject 2> Miley Cyrus nods with a warm expressive smile.
   ```
   Qwen3-VL outputs text embedding vectors where `<Subject 1>` is contextually bound to the semantic tokens *"pale blue-green eyes, dark hair, parted bangs, full lips"*, and `<Subject 2>` is bound to *"wavy honey-blonde hair, blue-grey eyes, radiant smile, arm tattoos"*.

2. **Visual Token Injection**:
   The 6 RefMods are placed into the DiT packed sequence at specific temporal cursor positions on the 3D RoPE coordinate grid.

3. **Attention Query-Key Dot Product**:
   When the DiT denoises the spatial region corresponding to `<Subject 1>` (e.g. left side of the screen):
   - The query vectors $\mathbf{Q}_{\text{left}}$ carry semantic conditioning from `<Subject 1>`'s text prompt (*dark hair, pale blue-green eyes*).
   - In the attention computation $\text{Softmax}\left(\frac{\mathbf{Q}\mathbf{K}^T}{\sqrt{d}}\right)\mathbf{V}$, the key vectors $\mathbf{K}$ from RefMods 1, 2, and 3 (which contain Billie Eilish visual latents) produce very high dot-product similarity scores.
   - The key vectors from RefMods 4, 5, and 6 (wavy blonde hair, different bone structure) produce low similarity scores and are suppressed by the softmax function.

4. **Self-Routing Execution**:
   Because of this high feature affinity, the DiT automatically routes the pixels of RefMods 1–3 into `<Subject 1>`'s physical form on the left, and the pixels of RefMods 4–6 into `<Subject 2>`'s physical form on the right.

## 5. Order Invariance & Permutation Behavior

### What If We Change the Order of RefMods?
**RefMod order is invariant.**

If you load the RefMods in reverse or mixed order:
- `Slot 1..3`: Miley Cyrus RefMods
- `Slot 4..6`: Billie Eilish RefMods
- Or alternating: `[Billie 1, Miley 1, Billie 2, Miley 2, ...]`

**Result**: The video generates **identically**. 

Why?
- Inside the DiT, attention is a permutation-equivariant operation across the packed sequence.
- Because each RefMod occupies its own non-overlapping segment on the RoPE grid, the model computes global attention across all reference tokens simultaneously.
- The text prompt's semantic features guide the attention heads to retrieve the correct visual tokens regardless of where they sit in the sequence table.

## 6. Complex Scenarios & Edge Cases

### 6.1 Asymmetric Stacks (e.g. 3 RefMods for Subject 1 vs. 1–2 RefMods for Subject 2)
What happens if Subject 1 has 3 RefMods and Subject 2 has only 1 or 2 RefMods?

| Aspect | Subject 1 (3 RefMods) | Subject 2 (1–2 RefMods) |
| :--- | :--- | :--- |
| **Token Count** | ~48 visual tokens | ~16–32 visual tokens |
| **Attention Pull** | Very strong "gravitational well" | Moderate "gravitational well" |
| **Likeness Lock** | Impervious to LoRA distortion | Moderately protected |
| **Risk Factor** | Minimal | Slight risk of facial drift under heavy LoRAs |

- **Outcome**: The generation works cleanly without crashes or crossover.
- **Best Practice**: If one character is undergoing extreme motion, rapid speech articulation, or heavy LoRA effects (e.g. speaking vigorously or rapid head turning), assign them 3 RefMods; if the second character is mostly passive/static in the shot, 1–2 RefMods is completely sufficient.

---

### 6.2 The Phenotypic Similarity Problem (Two Similar Personas)
What happens if `<Subject 1>` and `<Subject 2>` share similar broad features (e.g. both are fair-skinned women with light eyes)?

```
┌────────────────────────────────────────────────────────────────────────┐
│                        THE "IDENTITY BLEED" RISK                       │
├────────────────────────────────────────────────────────────────────────┤
│ If text descriptions are generic ("young woman with light eyes"),      │
│ attention heads cannot differentiate between Subject 1's RefMods and   │
│ Subject 2's RefMods. The model averages their features, producing two  │
│ identical-looking hybrid faces.                                        │
└────────────────────────────────────────────────────────────────────────┘
```

#### The Golden Disambiguation Rules for Lookalikes:
To achieve 100% identity separation between similar personas, you MUST provide high-contrast biometric discriminators in the prompt:

1. **Hair Length, Color & Style Differentiation**:
   - `<Subject 1>`: *"jet-black hair with soft signature parted bangs framing face"*
   - `<Subject 2>`: *"wavy honey-blonde hair cascading down shoulders in soft layers"*
2. **Facial Morphology & Features**:
   - `<Subject 1>`: *"soft rounded facial contours, defined natural eyebrows, full plush lips"*
   - `<Subject 2>`: *"high sculpted cheekbones, wide radiant smile, slender nose"*
3. **Signature Accessories, Markings & Wardrobe**:
   - `<Subject 1>`: *"oversized dark knit streetwear hoodie, silver hoop earring"*
   - `<Subject 2>`: *"fitted leather jacket, delicate illustrative line-art arm tattoos"*
4. **Explicit Spatial Anchoring**:
   - Specify screen positions in `integrated_multimodal_description`:
     `"<Subject 1> Billie Eilish stands on the screen left... <Subject 2> Miley Cyrus sits on the screen right..."`

### 6.3 Quad-RefMod Ensembles (Persona Identity + Body Shape Boosters)
A specialized application of stacking is combining **3 Persona RefMods** with **1 Body Shape RefMod** (e.g. `minimaxh3_bodyshape_v1_refmod` or `minimaxh3_bodyshape_athletic_v1_refmod`):

- **Slots 1–3**: Persona RefMods @ 1.0, 1.0, 0.80 (Facial & Persona Identity Lock)
- **Slot 4**: `minimaxh3_bodyshape_v1_refmod` @ 1.0 (Body Proportion & Silhouette Geometry Booster)

```
┌────────────────────────────────────────────────────────────────────────┐
│                      QUAD-REFMOD ATTENTION ROUTING                     │
├────────────────────────────────────────────────────────────────────────┤
│ • Head / Face Queries   ──► Attract Slots 1..3 (Persona RefMods)       │
│ • Torso / Body Queries  ──► Attract Slot 4 (bodyshape RefMod)          │
└────────────────────────────────────────────────────────────────────────┘
```

Because the prompt describes physique, posture, and full-body contours across the torso and limbs while describing the persona's facial features and hair in the upper frame, the DiT's spatial attention heads route the body shape reference specifically to somatic and postural coordinates without corrupting the persona's distinct facial identity.

### 6.4 Dual Audio Timbre Conditioning (Multi-Subject Spoken & Polyphonic Singing Duets)
In multi-subject setups, MiniMax-H3 supports independent voice conditioning for each subject by injecting separate audio reference latents into the DiT packed sequence:

- **`<Audio 1>` (`billieeilish_talk.mp3` or `sing.mp3`)**: Binds to `<Subject 1>` (Billie Eilish).
- **`<Audio 2>` (`mileycyrus_talk.mp3` or `sing.mp3`)**: Binds to `<Subject 2>` (Miley Cyrus).

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                   DUAL-PERSONA + DUAL-AUDIO SIMULTANEOUS TWO-SHOT                      │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ • <Subject 1> Billie Eilish (RefMods 1..3) ◄──► <Audio 1> (Intimate, breathy timbre)   │
│ • <Subject 2> Miley Cyrus   (RefMods 4..6) ◄──► <Audio 2> (Raspy, energetic timbre)    │
│                                                                                        │
│ Continuous unbroken shared two-shot:                                                   │
│ - Dialogue: Turn-taking conversational cadence without audio bleeding.                 │
│ - Polyphonic Singing: Independent simultaneous melody lines / counterpoint harmony.     │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## 9. Summary Checklist for Flawless RefMod Stacking

1. **Always use 2–3 distinct RefMod files per character** created from different dataset subsets, centroid crops, or training checkpoints.
2. **Set the primary RefMods to `1.00` and the tertiary/supplementary RefMod to `0.80`** to balance sharp micro-detail with robust macro geometry.
3. **Ground distinct biometric constants in `subject_definitions`** for every `<Subject N>` tag (haircut, eye color, facial bone structure, tattoos/piercings, wardrobe).
4. **Never rely on generic descriptions** when two subjects have similar features—differentiate them explicitly by cut, accessories, attire, and spatial positioning (`screen left` vs `screen right`).
5. **RefMod slot ordering is invariant**; semantic cross-attention handles token routing based on multimodal prompt feature affinity.
6. **Combine with Dual Audio References (`<Audio 1>`, `<Audio 2>`)** when generating multi-character dialogue or simultaneous singing duets for independent vocal timbres.
